# Contributing to whitebox-dedup

Contributions to `whitebox-dedup` are welcome. This document covers the workflow,
code standards, and the non-negotiable data privacy rule.

---

## Getting Started

1. Fork the repository and clone your fork.
2. Install dev dependencies:
   ```bash
   pip install -e ".[dev]"
   ```
3. Run the test suite to confirm a clean baseline:
   ```bash
   pytest tests/
   ```
4. Create a feature branch and open a pull request against `main`.

---

## Code Standards

- Python 3.10+ syntax only.
- `jellyfish` is the only string similarity library permitted. Do not add `python-Levenshtein`,
  `fuzzywuzzy`, or `rapidfuzz`.
- Do not import `pyearth`. The MARS model is implemented as pure arithmetic in
  `mars_scorer.py`. `scikit-learn` is an optional training-only dependency.
- No `scikit-learn` imports in any file under `whitebox_dedup/`. Only `trainer.py` may use it.
- All new features must have corresponding tests in `tests/`.
- Run `ruff check .` before submitting a pull request.

---

## Data Privacy Rule

**Real beneficiary records must never be committed to this repository.**

This rule is absolute and applies to every contributor without exception.

### What is permitted in version control

- Synthetic fixture files generated by `tests/fixtures/generate_fixtures.py`
- Model weight JSON files in `models/` (coefficients only, no training records)
- ICP calibration JSON files in `models/calibration/`
- Anonymised aggregate statistics (counts, percentages, summary tables)

### What is prohibited

- Any CSV, Excel, or database export containing real names, phone numbers, GPS coordinates,
  national ID numbers, dates of birth, or any other personally identifiable information
- Any file derived from real programme beneficiary data, even if partially anonymised
- Trained model files that embed individual-level information in their weights

### Why this rule exists

The training data for `text_only_v1` derives from agricultural programme beneficiary
registries collected in Nigeria. Those records belong to programme participants who
did not consent to their data being published in an open-source repository.
Publishing them would violate data protection obligations and the trust of programme
participants.

### Enforcement

Pull requests that include real personal data will be rejected immediately and the
data will be purged from the repository history. If you are unsure whether a file
contains personal data, do not commit it. Ask first.

## Adding a New Pre-trained Model

1. Train your model using `trainer.py` with your own labelled pairs.
2. Export the JSON file to `models/your_model_name.json`.
3. If you have a calibration set, export the ICP calibration to
   `models/calibration/your_model_name_icp.json`.
4. Update `models/README.md` with a description of the model.
5. Add the model name to `DeduplicationPipeline._MODEL_SELECTION_ORDER`
   in `whitebox_dedup/pipeline.py` with its required feature set.
6. Add tests in `tests/test_pipeline.py` covering model selection.

---

## Regenerating Test Fixtures

If you modify the fixture generator, regenerate all fixtures before committing:

```bash
python tests/fixtures/generate_fixtures.py
```

The seed is fixed at 42. The output must be deterministic. All 125 tests must
still pass after regeneration.

---

## Release Process

Releases are tagged on `main`. The version in `pyproject.toml` must be updated
before tagging. The wheel is built with:

```bash
pip install hatchling
python -m hatchling build
```
